# revm 资源生命周期设计

状态：历史设计提案。当前已实现的行为以 [资源说明](resources.md) 为准；本次统一目录不迁移或读取旧数据。

本方案定义临时资源、运行记录和持久数据的所有权、存放位置与清理规则。核心约定是：session 管理 VM 运行，volume 管理持久数据；删除 session 默认不删除 volume。用户应能重建 VM 环境，同时继续使用已有的容器和应用数据。

文中未实现的命令和行为仅为历史目标接口；当前使用方式以 [run](run.md)、[podman](podman.md) 和 [exec](exec.md) 文档为准。

## 原有问题

早期 session 默认位于 `~/.cache/revm/<id>/`，日志、socket、SSH key、解压后的 rootfs 和默认容器存储共用这个目录。删除缓存或清理 session 目录时，容易同时删除需要保留的数据。

早期原始磁盘在已记录版本与请求版本不匹配时会被删除并重建；容器磁盘缺少版本属性时也会重建。版本标记因此同时承担了格式识别和数据删除的职责，需要拆开。

## 资源分类

| 类别 | 内容 | 生命周期 |
| --- | --- | --- |
| Runtime | socket、PID、实例 SSH key、临时挂载等运行资源 | 实例退出并释放使用者后清理；崩溃后可回收 |
| Cache | 内置 Alpine 压缩包、按内容摘要标识的基础 rootfs | 无活跃引用时可以清理，下次使用时重建 |
| State | session 配置、volume 引用、运行记录、退出状态、日志 | 停止后保留，通过 session 或历史清理操作删除 |
| Data | 容器存储、revm 管理的持久 volume | 直到用户明确删除对应 volume |

运行锁的释放跟随运行生命周期；锁文件的存放位置和删除时机必须保证并发互斥，不能随实例目录任意删除。

基础 rootfs 缓存不可被工作负载修改。每次运行使用独立写入层或工作副本，其内容属于临时资源；实现可选择写时复制或独立副本，但必须保证实例之间不共享可写系统目录。较大的 rootfs 工作副本可放在 Cache 下的实例工作目录，不要求放入可能使用内存文件系统的 Runtime 目录。活跃工作副本不得被缓存清理操作回收。

## Session 与运行实例

session ID 是用户指定的稳定逻辑名称，例如 `dev`；instance ID 是每次启动生成的唯一标识。一个 session 同时最多运行一个实例。

session 记录保存启动配置、持久 volume 引用和最近运行信息。instance 记录保存本次运行的资源归属、开始时间、结束时间和退出结果。日志按 instance 分开，避免重复启动时混入同一份运行记录。

清理只能操作属于目标 instance 的临时资源。清理旧实例时，不能删除同名 session 新实例的 socket、工作副本或连接入口。session 互斥锁和 volume 使用锁按稳定标识管理；仅检查 PID 或 socket 是否存在不足以证明资源可以回收。

## 工作负载默认行为

### Run

`revm run` 默认执行一次性任务：

- guest 系统目录中的修改属于本次运行，结束后丢弃。
- host bind mount 的写入直接保留在宿主目录。
- 显式挂载的持久 volume 或外部磁盘保留。
- 默认保留运行记录、退出状态和日志，便于排查失败。

`--rm` 可作为后续接口，在结束后自动删除 session 及其运行记录和日志；显式挂载的持久数据仍保留。自动生成 session ID 可后续增加，不作为资源分离的前置条件。

### Podman

`revm podman --id dev` 使用可重建的 VM 系统环境和稳定的持久容器存储。默认存储由 revm 管理为独立 volume，例如显示为 `podman-dev`。

停止、重启或删除 session 均不自动删除该 volume。再次使用相同 session ID 启动时，默认重新连接原有存储。默认 volume 与逻辑 session 名称的关联必须保存在 volume 元数据中，不能仅依赖可删除的 session 记录。实现应检测名称或关联冲突，并报错要求明确选择，不能悄悄创建空磁盘替代已有数据。

volume 初期只需由 raw/ext4 镜像和元数据组成，不要求引入独立存储服务。

## 磁盘所有权与版本

| 来源 | revm 的生命周期权限 |
| --- | --- |
| 自动创建的临时磁盘 | 实例结束后可以删除 |
| revm 管理的持久 volume | 可以挂载和检查；仅通过明确的 volume 删除或重置操作清除数据 |
| 用户指定的 `--raw-disk /path` 或 `--container-disk /path` | 可以按挂载配置使用；不自动删除、重建或纳入 volume 清理 |

用户指定的路径即使最初不存在、文件由 revm 创建，也属于用户指定的持久资源。外部磁盘和 host bind mount 不因被某个 session 引用而转归 revm 所有。

版本处理遵循以下规则：

- 缓存格式或基础 rootfs 内容变化时，可以生成新的缓存。
- 持久磁盘格式变化时，兼容读取、显式迁移，或返回说明升级办法的错误。
- 缺少版本元数据时，按未知格式检查；不能据此认定数据可以丢弃。
- 格式版本、用户提供的版本标签和删除授权分开表达；启动参数中的版本变化不授权删除数据。

需要清空 revm 管理的持久数据时，使用独立的 `volume reset` 一类操作。该操作必须明确目标，并拒绝操作正在使用的卷。外部磁盘的删除和重建由用户自行管理。

## 清理接口

以下名称用于表达接口语义，具体参数形式可在实现时确定。

| 建议操作 | 作用 | 持久数据 |
| --- | --- | --- |
| `stop dev` | 停止 VM，释放本次运行资源 | 保留 |
| `rm dev` | 删除已停止 session 的记录、日志和残留运行文件 | 保留 |
| `run --rm ...` | 正常退出或失败后自动执行 session 清理 | 显式持久数据保留 |
| `cache prune` | 清理未被活跃实例引用的可重建缓存和已确认失效的工作副本 | 不触及 |
| `volume rm NAME` | 删除明确指定且未被使用的 revm 管理卷 | 删除指定卷 |

`rm` 默认拒绝删除运行中的 session。volume 删除后，引用该卷的既有 session 应明确报告卷缺失，不得静默重新创建并伪装成原有存储。若将来支持一次删除 session 及关联卷，必须使用显式选项并列出目标卷。

崩溃回收先取得相应互斥锁并确认实例归属和活跃引用，再释放挂载、关闭资源、清理文件。无法确认资源是否仍在使用时保留资源并报告原因。外部符号链接只有在仍指向目标实例时才可清理，不能跟随链接删除外部目标。

## 目录布局

路径解析集中封装，Runtime、Cache、State 和 Data 均位于同一个 `REVM_HOME` 下，默认 `~/.revm`；Linux 和 macOS 使用相同布局：

~~~text
$REVM_HOME/run/<instance>/
  socks/

$REVM_HOME/cache/
  build/v1/
  instances/<instance>/

$REVM_HOME/state/sessions/<id>/
  session.json
  runs/<instance>/
    result.json
    logs/revm.log
    logs/vm.log

$REVM_HOME/data/volumes/<name>/
  volume.json
  disk.ext4
~~~

volume 元数据记录稳定 ID、名称、用途和磁盘格式；不保存默认 session 关联。session 元数据只引用 volume，不拥有其删除权限。实例结果记录区分命令退出、启动失败和异常终止；无法恢复的退出状态记录为未知，不能推断为成功。

Runtime 目录必须私有且路径足够短，避免 home 路径与 session 名组合后超过 Unix socket 路径限制。session 名通过状态记录解析到实例，不直接拼接为无限增长的 socket 路径。路径过长时明确报错并要求缩短 REVM_HOME，不回退到根目录外；这些平台限制不改变资源生命周期。

仅统一根目录可以配置，配置只能改变位置，不能改变资源的所有权。Cache 和 Data 保持独立子目录。清理操作按元数据和资源归属执行，不能将自定义目录内的所有文件都视为 revm 所有。

## 旧目录兼容与迁移

新版本仅使用统一目录，不读取、迁移或清理旧 XDG 目录和 `~/.cache/revm/<id>/`。切换版本或 REVM_HOME 前应停止旧实例。旧 session、日志和磁盘保持原样；需要继续使用外部磁盘时，通过 `--container-disk PATH` 显式指定。本次不提供迁移命令。

## 实施顺序与验收

优先实施：

1. 停止在启动路径中自动删除持久磁盘，明确未知版本和不兼容格式的错误行为。
2. 将默认容器磁盘归为独立持久 volume；旧数据迁移另行设计。
3. 分离 session 清理与 volume 删除，引入实例归属和并发保护。
4. 分离缓存、运行记录和临时资源，再增加 `--rm`、缓存清理等使用接口。

验收应覆盖以下行为：

- 停止或删除 Podman session 后，原 volume 内容不变；同名重建默认复用原存储。
- `run --rm` 同时清理成功和失败运行的临时资源与记录，但保留显式 volume、外部磁盘和 bind mount 内容。
- guest 系统目录写入不进入共享基础 rootfs，也不影响下一次运行或其他实例。
- 版本不匹配、缺少版本属性和格式不兼容均不会自动删除持久数据。
- 缓存清理保留活跃工作副本、持久卷和尚未分类的旧 session 数据。
- 旧实例清理与同名新实例启动并发时，新实例资源不受影响。
- 卷被使用时拒绝删除；卷已显式删除时，已有引用报告缺失，不静默新建。
- 新版本不会读取、迁移或清理旧数据。
